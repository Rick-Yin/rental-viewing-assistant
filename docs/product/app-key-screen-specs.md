# App 关键屏设计规格

## 1. 房源列表

### 目标

帮助用户快速扫描所有房源，并知道每套房源下一步该做什么。

### 首屏信息

- 房源状态分组或筛选入口
- 当前签约中提示
- 搜索入口
- 房源卡片列表
- 新增房源 FAB

### 房源卡片

卡片只保留以下信息：

- 标题 / 小区
- 月租与押付
- 状态 chip
- 最高风险或待确认项
- 下一步动作
- 总分或风险计数

评分维度、完整看房记录、联系人、材料和 AI 解释不放在列表卡片中。

### 空状态

空列表优先引导新增真实房源：

- 主按钮：新增第一套房源
- 次级入口：完善租房偏好
- 示例数据不作为主入口，可放到使用指引或设置里的演示模式。

## 2. 房源详情

### 目标

让用户理解单套房源是否值得继续推进，以及下一步该做什么。

### 页面结构

- 顶部：房源标题、状态、更多操作。
- 信息区：租金、押付、户型、面积、楼层、朝向、位置。
- 时间线：看房记录列表，可新建看房记录。
- 评分区：综合分与 6 个维度摘要。
- 操作区：主操作、次级操作、危险操作分层。

### 操作分层

- 主操作：只显示当前阶段最重要的一件事。
- 次级操作：编辑、照片备注、AI 分析、进入对比。
- 危险操作：排除、删除，放在底部并需要确认。

## 3. 看房 Checklist

### 目标

支持用户在看房现场快速做结构化记录。

### 页面结构

- 顶部摘要卡：房源标题、租金、地址、看房进度、风险/不确定计数。
- 分组 checklist：按模块折叠。
- item 卡片：标题、oneLine、优先级、当前状态。
- 底部或悬浮快捷入口：拍照、备注。

### 交互

- 三态按钮：OK、风险、不确定。
- 默认优先展开高风险、未检查或推荐模块。
- 点击 item 进入详情页。
- item 详情页顶部直接提供三态按钮和备注输入。
- 详情页参考区顺序：风险信号、怎么查、拍照建议、记录建议、为什么查、参考链接。

## 4. 对比决策

### 目标

帮助用户从候选房源中收敛选择。

### 页面结构

- 顶部决策摘要：推荐推进房源、推荐理由、主要风险、待复核点。
- 候选房源卡片式对比：手机端不以横向大表格为主视图。
- 维度切换：租金、总分、交通、环境、户型、设施、风险、性价比。
- 操作：查看详情、进入签约、排除。

### 约束

- 0 套候选：提示先添加或恢复候选房源。
- 1 套候选：提示至少需要 2 套候选房源才能对比。
- 已有签约中房源：其他房源的进入签约动作禁用，并说明当前签约房源。

## 5. 签约总览

### 目标

签约前优先处理阻断项，避免用户被材料和 checklist 细节淹没。

### 页面结构

- 顶部：签约房源摘要、签约进度、风险/不确定/未检查计数。
- 签前阻断项：必须确认、建议补充、可稍后处理。
- 入口卡片：签约 checklist、签约材料、AI 审查。
- 终态操作：已签约、签约放弃。

### 交互

- 默认展开有风险或不确定的模块。
- 完全 OK 的模块默认折叠。
- 点击已签约必须弹确认。
- 点击签约放弃必须弹确认，并允许填写放弃原因。
- 如果仍有必须确认项，确认弹窗要提醒用户人工核验。

## 开发交接标注要求

每个关键屏设计稿必须标注：

- 读取的数据对象。
- 写入的数据对象。
- 触发的状态迁移。
- 主按钮的前置条件。
- 空状态、错误状态和禁用状态。
- 敏感字段是否默认展示。
