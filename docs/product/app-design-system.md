# App 设计系统任务

## 设计目标

设计系统服务于任务型租房工具，而不是营销型页面。界面应安静、清晰、可扫描，优先帮助用户完成记录、比较和签约核查。

## 核心组件

| 组件 | 用途 |
| --- | --- |
| Top App Bar | 页面标题、返回、更多操作 |
| Bottom Navigation | 房源、对比、签约、我的 |
| FAB | 新增房源或当前页面核心创建动作 |
| Property Card | 房源列表主卡片 |
| Status Chip | 房源状态、风险状态 |
| Risk Block | 最高风险、待确认项、阻断项 |
| Score Badge | 总分和维度评分 |
| Checklist Item | 看房/签约核查项 |
| Decision Summary | 对比页顶部推荐摘要 |
| Signing Blocker Card | 签前阻断项 |
| Bottom Sheet | 更多操作、选择器、删除确认前置菜单 |
| Dialog | 确认、放弃原因、导入错误 |
| Toast | 轻量反馈 |
| Empty State | 空列表、对比不足、无签约中房源 |

## 状态色与图标

| 状态 | 颜色语义 | 图标建议 |
| --- | --- | --- |
| OK | 正向 / 绿色 | check |
| 风险 | 危险 / 红色 | warning |
| 不确定 | 提醒 / 黄色 | help |
| 待看房 | 信息 / 蓝色 | calendar |
| 候选 | 正向 / 绿色 | star |
| 签约中 | 注意 / 橙色 | contract |
| 已签约 | 完成 / 绿色 | check-circle |
| 已排除 | 危险 / 红色 | x-circle |
| 已归档 | 中性 / 灰色 | archive |

不能只靠颜色表达状态，必须同时使用文字或图标。

## 触控规则

- 主按钮高度不低于 48px。
- 图标按钮目标区域为 40-48px。
- checklist 三态按钮优先使用大触控区。
- chip 最小高度 32px。
- 列表最后一张卡片必须留出底栏和 FAB 安全区。
- 弹窗底部按钮不得贴近系统手势区域。

## 信息密度规则

- 列表卡片只回答：这是什么、多少钱、现在什么状态、最大风险是什么、下一步做什么。
- 详情页再展示评分维度、历史记录、联系人和材料。
- 签约页优先展示阻断项，材料和完整 checklist 放二级入口。
- 对比页移动端优先使用卡片和维度切换，不把横向大表格作为主视图。

## 页面模板

### 列表页模板

- 顶部标题
- 搜索/筛选/排序
- 状态摘要或横幅
- 列表卡片
- FAB
- 底栏

### 详情页模板

- 顶部标题与状态
- 事实摘要
- 时间线或分组内容
- 主操作区
- 次级操作区
- 危险操作区

### 检查流模板

- 摘要卡
- 分组 checklist
- 快捷拍照/备注
- item 详情页三态操作区

### 决策页模板

- 决策摘要
- 对比维度切换
- 候选卡片
- 行动按钮

## 深色模式

深色模式必须覆盖：

- 页面背景
- surface/container
- 表单输入
- 弹窗和 bottom sheet
- 状态 chip
- 风险色
- 海报预览外壳
- AI 分享预览

海报本体可以使用固定浅色主题，但需要在保存前提示其为分享卡样式。
