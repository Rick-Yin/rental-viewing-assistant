# App 设计阶段任务包

## 目标

本阶段把 HTML 原型中已经验证的体验，收束成 Android MVP 可实现的 App 设计资产。重点不是继续增加功能，而是固定主链路、页面职责、状态机、组件语言、隐私与 AI 边界。

## 阶段原则

- 先做产品设计收束，再做高保真和开发交接。
- 先固定 5 个关键屏，再扩展画像、设置、AI、海报和材料页。
- HTML 原型继续作为体验参考，不作为正式 App 代码迁移基础。
- App 数据模型以 `docs/核心数据模型.md` 为准，不沿用原型中的扁平 `properties[]`。

## MVP 功能分层

### 首版主链路

- 房源列表
- 房源详情
- 看房记录
- 看房 checklist
- 多房源对比
- 签约总览
- 签约 checklist
- 签约终态：已签约 / 签约放弃

### 首版辅助能力

- 租房画像
- 模板推荐
- AI 分享与导入
- 数据导出
- 使用指引
- 签约材料记录
- 看房照片与备注

### 后续版本

- 日历
- 统计
- 海报多模板
- 入住准备
- 复杂同步
- 账号系统
- 打赏入口

## 首轮关键屏

首轮 App 设计只要求完成以下 5 个关键屏的低保真、高保真和组件标注：

| 页面 | 主任务 | 主按钮 | 次级入口 | 危险操作 |
| --- | --- | --- | --- | --- |
| 房源列表 | 扫描所有房源并判断下一步 | 新增房源 | 搜索、筛选、排序、进入对比、进入签约 | 批量删除不进入首版 |
| 房源详情 | 理解单套房源状态和记录完整度 | 当前状态对应的下一步 | 编辑、看房记录、照片备注、AI 分析、对比 | 排除、删除 |
| 看房 checklist | 现场快速完成结构化检查 | 保存检查结果 | 拍照、备注、item 详情 | 清空记录不进入首版 |
| 对比决策 | 在候选房源中收敛选择 | 进入签约 | 查看详情、排序、排除 | 退出签约不在此页 |
| 签约总览 | 处理签前阻断项并形成终态 | 处理必须确认项 | 签约 checklist、材料、AI 审查 | 已签约、签约放弃 |

## 主链路

首版主链路固定为：

```text
新增房源 -> 待看房 -> 已看房 -> 候选 -> 签约中 -> 已签约 / 放弃
```

每个状态只能有一个最突出的主行动：

| 状态 | 用户心智 | 主行动 |
| --- | --- | --- |
| `draft` | 刚建档，信息不完整 | 继续补充或记录看房 |
| `to_view` | 准备看房 | 记录看房 |
| `viewed` | 已看过，待整理 | 补 checklist 或加入候选 |
| `shortlisted` | 值得比较 | 进入对比或进入签约 |
| `signing` | 进入签前核查 | 处理签前阻断项 |
| `signed` | 已完成 | 查看归档信息 |
| `signing_abandoned` | 签约已放弃 | 查看放弃原因 |
| `rejected` | 已排除 | 查看排除原因或恢复候选 |
| `archived` | 不再活跃 | 查看归档信息 |

## 交付物

- App MVP 页面清单
- 核心状态机和页面流转图
- 5 个关键屏线框稿
- 5 个关键屏高保真稿
- App 组件清单与状态规范
- 隐私与 AI 信任设计说明
- 开发交接标注：每页的数据读取、写入、状态迁移、错误提示

## 验收标准

- 用户能在 3 分钟内新增一套房源并进入看房记录。
- 用户能在现场快速完成 checklist 三态标记。
- 用户能从 2 套以上候选房源进入对比，并理解推荐理由。
- 用户能从对比页进入签约，并看到签前阻断项。
- 每个核心页面只有一个清晰主行动。
- 风险、状态、下一步动作在首屏可见。
- 小屏下 FAB、底栏、弹窗不遮挡关键操作。
- AI 分享和海报分享都有脱敏预览。
- 签约建议文案不承诺法律结论。
