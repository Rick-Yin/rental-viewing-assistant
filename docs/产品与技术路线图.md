# 产品与技术路线图

## 文档目的

本文档用于统一项目在未来几个阶段的产品目标、技术策略与交付顺序，避免在需求尚未稳定时过早扩展平台、后端或复杂功能。

## 产品目标

`rental-viewing-assistant` 的核心目标是帮助用户在多次看房过程中高质量记录信息，并在选中房源后完成签约前风险核查。

项目优先解决以下问题：

- 看房信息分散在聊天、相册、备忘录中，难以回顾。
- 多套房源比较时主观印象失真，难以做结构化决策。
- 看房当场无法快速记录重点，事后信息丢失。
- 进入签约阶段后，条款、费用和责任边界难以系统核查。

## 开发原则

### 1. 先闭环，后扩展

优先打通一条真实可用的主流程，而不是同时做很多边缘能力。

### 2. 先 Android，后多端

Android 是首发平台；iOS 和 HarmonyOS 在业务边界稳定后推进。

### 3. 先离线可用，后云同步

看房和签约场景都可能发生在网络不稳定环境，本地可用性优先于在线能力。

### 4. 先结构化记录，后智能化分析

没有稳定、可复用的数据结构，任何 AI 或推荐功能都只是表面增强。

## 阶段路线图

## 第一阶段：Android MVP

目标是在单端完成“看房 -> 对比 -> 签约核查 -> 已签/放弃”的核心业务闭环。

### 交付物

- 房源列表
- 租房画像与模板推荐
- 房源详情
- 看房记录创建与编辑
- 看房结构化检查项
- 文字笔记与照片记录
- 评分卡
- 多房源对比页
- 签约阶段入口与状态切换
- 签约 checklist
- 签约材料记录
- 签约 AI 审查结果页
- 已签约 / 签约放弃终态
- 本地持久化
- 基础导出能力

### 完成标准

用户可以独立完成一次从新增房源、连续看房、多房对比，到选出一套房并完成签约核查的完整流程。

## 第二阶段：稳定化与可迁移改造

目标是在不引入复杂多端成本的前提下，固化可共享能力。

### 重点内容

- 数据模型收敛
- 数据库迁移方案
- 导出格式标准化
- 媒体文件命名与索引规范
- 仓储接口抽象
- 同步协议预留

## 第三阶段：iOS 接入

目标是在业务层稳定后支持第二平台。

### 原则

- 优先共享领域模型和业务规则。
- 不强行共享 UI。
- iOS 端应保持符合平台习惯的体验。

## 第四阶段：同步、备份与账号体系

目标是让用户在多设备间安全地保留数据，并支持换机与备份恢复。

### 重点内容

- 本地导入导出
- 云端备份与恢复
- 账号体系
- 冲突处理策略
- 媒体上传与引用关系

## 第五阶段：HarmonyOS 接入

目标是在共享业务层、数据结构和同步方案稳定后支持第三平台。

### 原则

- 共享数据与规则，不预设共享 UI。
- 优先确保核心功能一致性。
- 平台特性适配放在功能等价之后。

## 当前首要任务

当前最重要的工作不是继续扩平台，而是完成 Android MVP 中最关键的一条垂直切片：

`新增房源 -> 多套看房 -> 填写结构化记录 -> 拍照/备注 -> 完成评分 -> 加入对比 -> 选中签约 -> 签约核查 -> 已签/放弃`

只有这条链路稳定后，后续架构和平台扩展的方向才有意义。

## 近期里程碑

### 里程碑 M1：数据骨架可用

- 定义租房画像、模板选择和模板推荐原因的数据结构
- 定义房源、看房记录、签约会话、评分卡、媒体资源等核心实体
- 完成本地数据库建模
- 建立仓储接口

### 里程碑 M2：看房流程可演示

- 完成租房画像表单和模板推荐结果确认
- 完成新增房源
- 完成看房表单
- 完成照片与备注关联
- 完成评分与总览

### 里程碑 M3：签约流程可演示

- 完成签约阶段入口
- 完成签约 checklist
- 完成签约材料记录
- 完成签约 AI 审查结果展示

### 里程碑 M4：决策价值可验证

- 完成房源对比页
- 完成签约终态记录
- 完成导出摘要
- 完成用户试用反馈整理

### 里程碑 M5：为第二平台做准备

- 完成领域层收敛
- 收敛 UI 状态模型
- 固化导出与同步协议

## 不建议当前阶段投入的事项

- 复杂推荐算法
- 大规模云端架构
- 聊天式 AI 助手
- 多端共享 UI 框架试验
- 深度地图与通勤智能分析
- 签约阶段的 PDF、录音和外链材料解析

这些能力都可能有价值，但不应早于核心闭环验证。
