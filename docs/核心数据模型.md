# 核心数据模型

## 设计原则

数据模型应围绕“房源生命周期”展开，而不是围绕单个页面设计。当前生命周期分成两个阶段：

- 看房阶段：允许多套房源并行记录和比较
- 签约阶段：仅对一套已选房源执行签约核查

## 生命周期规则

- 用户可以先创建或更新一个 `RentalProfile`，再基于该画像生成 `ChecklistTemplateSelection`
- 一个 `Property` 在看房阶段可以有多条 `Viewing`
- 一个 `Property` 在被选中后可以进入 `SigningSession`
- 同一时间全局只允许一个活跃 `SigningSession`
- `ComparisonEntry` 仅服务于看房阶段
- 签约阶段终态只有 `signed` 和 `signing_abandoned`

## 核心实体

## 1. 租房画像 `RentalProfile`

表示用户在选择模板前填写的一组轻量偏好和场景信息。

### 建议字段

- `id`
- `tenantType`
- `gender`
- `specialPurposes`
- `coLivingType`
- `hasPet`
- `hasChildren`
- `rentalRegion`
- `notes`
- `createdAt`
- `updatedAt`

### 说明

`RentalProfile` 只用于本地模板推荐。性别、陪护、孩子、宠物等字段都应允许为空，不应默认出现在导出或 AI 分享内容中。

## 2. 模板选择 `ChecklistTemplateSelection`

表示某次租房周期中实际启用的模板组合。

### 建议字段

- `id`
- `rentalProfileId`
- `viewingTemplateCodes`
- `signingTemplateCodes`
- `recommendationReasons`
- `manuallyEdited`
- `createdAt`
- `updatedAt`

### 说明

模板推荐结果应可被用户手动修改。`recommendationReasons` 用于解释推荐原因，例如“有宠物，增加宠物条款核查”。

## 3. 房源 `Property`

表示一个待租房源的主对象。

### 建议字段

- `id`
- `title`
- `communityName`
- `address`
- `district`
- `rentAmount`
- `depositRule`
- `agencyFee`
- `layoutText`
- `areaSquareMeter`
- `floorInfo`
- `orientation`
- `contactName`
- `contactPhone`
- `sourcePlatform`
- `listingUrl`
- `status`
- `workflowStage`
- `selectedForSigningAt`
- `createdAt`
- `updatedAt`

### 说明

一个房源可以关联多条看房记录，也可以在尚未实地看房前先建立基础档案。

## 4. 看房记录 `Viewing`

表示一次真实的到场或远程看房事件。

### 建议字段

- `id`
- `propertyId`
- `scheduledAt`
- `visitedAt`
- `transportSummary`
- `firstImpression`
- `noiseLevel`
- `odorLevel`
- `cleanlinessLevel`
- `lightingLevel`
- `ventilationLevel`
- `agentAttitude`
- `riskSummary`
- `notes`
- `createdAt`
- `updatedAt`

### 说明

同一房源可能存在多次看房，例如白天和晚上各看一次，因此 `Property` 与 `Viewing` 是一对多关系。

## 5. 看房检查项结果 `ViewingChecklistResult`

表示一次看房中某个检查项的结构化结果。

### 建议字段

- `id`
- `viewingId`
- `categoryCode`
- `itemCode`
- `resultValue`
- `severity`
- `comment`
- `createdAt`
- `updatedAt`

### 说明

检查项要使用稳定编码，不应直接把页面文案当作主键。

## 6. 看房媒体资源 `ViewingMediaAsset`

表示与房源或看房记录关联的图片资源。

### 建议字段

- `id`
- `propertyId`
- `viewingId`
- `fileName`
- `filePath`
- `mimeType`
- `capturedAt`
- `note`
- `sortOrder`
- `createdAt`

## 7. 评分卡 `ScoreCard`

表示某次看房或某个房源在多个维度上的评分结果。

### 建议字段

- `id`
- `propertyId`
- `viewingId`
- `transportScore`
- `environmentScore`
- `layoutScore`
- `facilityScore`
- `riskScore`
- `pricePerformanceScore`
- `totalScore`
- `scoringVersion`
- `createdAt`
- `updatedAt`

### 说明

评分算法必须带版本号，避免未来调整规则后旧数据无法解释。

## 8. 对比条目 `ComparisonEntry`

表示用户将某个房源加入当前对比集合。

### 建议字段

- `id`
- `propertyId`
- `selected`
- `pinned`
- `userConclusion`
- `decisionTag`
- `createdAt`
- `updatedAt`

## 9. 签约会话 `SigningSession`

表示某套房源被选中后进入签约核查阶段的主对象。

### 建议字段

- `id`
- `propertyId`
- `status`
- `startedAt`
- `decidedAt`
- `counterpartyRole`
- `counterpartyName`
- `counterpartyContact`
- `decisionNotes`
- `createdAt`
- `updatedAt`

### 说明

同一时间只允许一个活跃的 `SigningSession`，这样产品语义和状态管理都更稳定。

## 10. 签约检查项结果 `SigningChecklistResult`

表示签约核查中某个条款或责任边界的结构化检查结果。

### 建议字段

- `id`
- `signingSessionId`
- `categoryCode`
- `itemCode`
- `resultValue`
- `severity`
- `comment`
- `createdAt`
- `updatedAt`

## 11. 签约材料 `SigningMaterialAsset`

表示签约阶段用于核查的文字材料或图片材料。

### 建议字段

- `id`
- `propertyId`
- `signingSessionId`
- `materialType`
- `title`
- `textContent`
- `fileName`
- `filePath`
- `mimeType`
- `capturedAt`
- `note`
- `sortOrder`
- `createdAt`

## 枚举建议

以下字段建议使用枚举或稳定编码：

- `status`
- `workflowStage`
- `decisionTag`
- `tenantType`
- `gender`
- `specialPurposes`
- `coLivingType`
- `noiseLevel`
- `odorLevel`
- `cleanlinessLevel`
- `resultValue`
- `severity`
- `sourcePlatform`
- `materialType`
- `counterpartyRole`

## 关系概览

- 一个 `Property` 可以有多个 `Viewing`
- 一个 `Viewing` 可以有多个 `ViewingChecklistResult`
- 一个 `Viewing` 可以有多个 `ViewingMediaAsset`
- 一个 `Viewing` 可以对应一个或多个 `ScoreCard`
- 一个 `Property` 可以进入一个或多个 `ComparisonEntry`
- 一个 `Property` 在被选中后可以有一个 `SigningSession`
- 一个 `SigningSession` 可以有多个 `SigningChecklistResult`
- 一个 `SigningSession` 可以有多个 `SigningMaterialAsset`
- 一个 `RentalProfile` 可以生成一个或多个 `ChecklistTemplateSelection`
- 一个 `ChecklistTemplateSelection` 可以被多个房源和看房记录复用

## 导出建议

导出时建议拆为两部分：

### 结构化导出

使用 JSON 保存房源、看房记录、签约会话、检查项、评分等结构化数据。

### 媒体导出

使用独立目录保存看房照片和签约图片，并通过相应资源对象中的标识与结构化数据关联。

## 向后兼容要求

为了支持未来升级，以下字段建议从第一版就引入：

- `updatedAt`
- `scoringVersion`
- `schemaVersion`
- 稳定 `id`
- `workflowStage`

这些字段短期看似多余，但能显著降低未来做迁移、同步和多端共享时的成本。
